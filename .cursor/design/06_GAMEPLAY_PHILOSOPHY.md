# Gameplay Philosophy

Gameplay is not about winning battles.

Gameplay is about creating unforgettable stories.

Every mechanic should increase the number of meaningful decisions, memorable moments, and opportunities for teamwork.

The game should reward communication more than individual mastery.

---

# The Crew Is The Hero

No single player should solve every problem.

Every station should occasionally become the most important station on the ship.

The pilot cannot win alone.

The engineer cannot win alone.

The gunner cannot win alone.

The scientist cannot win alone.

The most memorable victories occur when every crew member contributes.

---

# Communication Is Gameplay

Communication should not merely support gameplay.

Communication IS gameplay.

Players should naturally exchange:

- observations
- warnings
- discoveries
- plans
- failures
- requests
- celebrations

Silence should rarely be the optimal strategy.

---

# Decisions Over Execution

Interesting decisions are more valuable than mechanical difficulty.

Whenever possible, challenge players to decide:

- What is the greatest threat?
- What should we repair first?
- Should we press forward or retreat?
- Should we spend ammunition now?
- Is this side objective worth the risk?
- Can we save another crew?
- Do we trust this faction?

The game should regularly ask players difficult questions rather than merely difficult actions.

---

# Every System Should Create Stories

Features are valuable when they interact.

The best moments happen when several systems unexpectedly combine.

Avoid isolated mechanics.

Prefer interconnected systems that allow emergent situations.

---

# Failure Creates Better Stories

Failure is not the opposite of fun.

Failure often creates the most memorable moments.

The game should support:

- recovery
- improvisation
- heroic sacrifice
- unexpected victories
- desperate plans

Avoid designs where one mistake immediately ends the experience.

---

# Downtime Is Valuable

Constant action reduces tension.

Periods of calm allow players to:

- repair
- reload
- explore
- joke
- tell stories
- admire the world
- prepare

Quiet moments make exciting moments more meaningful.

---

# Curiosity Should Be Rewarded

Players should feel encouraged to investigate.

Rewards may include:

- resources
- lore
- shortcuts
- technology
- discoveries
- beautiful scenery
- memorable encounters

Not every reward needs gameplay value.

Wonder has value.

---

# Simplicity Before Complexity

A small number of well-connected systems is more valuable than many isolated mechanics.

New mechanics should deepen existing gameplay before introducing entirely new categories of play.

Depth should emerge from interaction rather than quantity.

---

# Graybox Before Polish

Gameplay should prove itself before visual polish.

Questions to answer first:

- Is driving enjoyable?
- Is combat satisfying?
- Is engineering meaningful?
- Is exploration engaging?
- Does communication happen naturally?
- Do memorable stories emerge?

Art should amplify good gameplay.

It should not compensate for weak gameplay.

---

# Respect Player Time

Every activity should justify the player's attention.

Travel should create opportunities.

Combat should create decisions.

Exploration should create discovery.

Downtime should create anticipation.

If an activity creates none of these, reconsider it.

---

# The Final Test

Before adding any mechanic, ask:

Does this create more opportunities for memorable stories?

Does it encourage cooperation?

Does it increase meaningful decisions?

Does it reinforce the fantasy of being a crew?

If not, it probably does not belong.
